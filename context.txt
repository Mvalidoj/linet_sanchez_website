# 5. VISUAL IDENTITY AND DESIGN SYSTEM

This is one of the most important parts of the project.

All future components, pages, layouts, and interactions must follow this visual system.

## 5.1 Design philosophy

The visual language is:

**Architectural Editorial Minimalism.**

It combines:

- Contemporary art editorial design.
- Minimalist architecture.
- Artist photobooks.
- Museum and gallery exhibition design.
- Cinematic photographic composition.

Five principles must guide every design decision.

### A. Architecture and Space

Use precise grids, geometric relationships, structured compositions, and deliberate alignment.

### B. Absence and Emptiness

Negative space is a fundamental design element.

Do not fill empty areas simply because they exist.

Give artworks, typography, and compositions room to breathe.

### C. Memory and Time

The website must feel contemplative and timeless.

Use carefully controlled visual rhythm, editorial sequencing, and restrained transitions.

### D. Theatricality

Treat images as scenes or spatial experiences.

Use cinematic framing, large images, and deliberate compositions.

### E. Reconstruction and Introspection

Use modular layouts, asymmetry, and subtle changes in scale to create a sense of discovery.

- Related content spacing: 24–48px.
- Dividers: 1px, approximately #D3D1CA.
- Default border radius: 0px.

Grid:

- Desktop: 12 columns.
- Tablet: 6 columns.
- Mobile: 4 columns.

# 7. RESPONSIVE DESIGN

The entire website must be responsive.

Desktop: 1200px and above.

Tablet: 768px–1199px.

Mobile: below 768px.

Reference viewport sizes:

- 1440 × 900.
- 1280 × 800.
- 1024 × 768.
- 768 × 1024.
- 390 × 844.
- 375 × 812.

The responsive design must be intentional.

Do not simply shrink desktop elements.

On mobile:

- Use a natural single-column reading flow.
- Preserve artwork aspect ratios.
- Maintain readable typography.
- Simplify complex grid compositions.
- Reduce spacing carefully without eliminating negative space.
- Prevent horizontal overflow.
- Keep navigation accessible.

No section may create unintended horizontal scrolling.

---

# 8. INTERACTION AND MOTION

Motion must be subtle and purposeful.

Recommended timings:

- Hover: 200ms.
- Menu: 250ms.
- Image reveal: 500ms.
- Page transitions, if appropriate: 300ms.

Permitted interactions:

- Subtle image reveal.
- Very gentle image zoom, maximum scale 1.02.
- Navigation underline or opacity transitions.
- Smooth anchor navigation.
- Accessible mobile menu.
- Artwork lightbox when relevant.
- Previous/next navigation inside a project gallery.

Avoid:

- Auto-playing carousels.
- Excessive parallax.
- Custom cursors.
- Decorative 3D.
- Auto-playing audio.
- Distracting animations.

Respect `prefers-reduced-motion`.

All interactive elements must support keyboard navigation.

# 12. PERMANENT OPERATING RULES FOR FUTURE SESSIONS

These rules must be included in CLAUDE.md and followed in every future task.

## Rule 1 — Read project context first

Before making changes, read CLAUDE.md and the documentation relevant to the requested task.

Do not assume that previous conversation context is sufficient.

The repository documentation is the persistent source of truth.

## Rule 2 — Preserve the design system

Never introduce a new color, font, spacing convention, border treatment, or interaction pattern without a clear reason.

Reuse existing design tokens.

If a new token is necessary, document it before or alongside its implementation.

## Rule 3 — Preserve the artistic identity

Every visual decision must reinforce the concept:

"THE ARCHITECTURE OF MEMORY".

Do not introduce generic templates or fashionable visual elements that contradict the established art direction.

## Rule 4 — Respect existing implementations

Before modifying a component, inspect its existing implementation and dependencies.

Prefer extending existing reusable components over creating duplicate implementations.

Do not rewrite working architecture without justification.

## Rule 5 — Work incrementally

Implement only the requested phase or feature.

Do not anticipate future features by building unnecessary infrastructure.

Do not implement multiple pages when the request concerns only one.

## Rule 6 — Maintain responsive consistency

Every new component or page must work on desktop, tablet, and mobile.

Responsive behavior must follow RESPONSIVE_DESIGN.md.

## Rule 7 — Do not invent content

Never invent:
- Artist biography details.
- Artwork titles.
- Dates.
- Exhibitions.
- Publications.
- Awards.
- Materials.
- Dimensions.
- Curators.
- Galleries.

Use only verified information.

Mark missing information explicitly.

## Rule 8 — Protect artwork integrity

Never crop, recolor, distort, or modify artworks in ways that compromise their original presentation.

Use actual artwork assets.

If placeholders are necessary, identify them clearly.

## Rule 9 — Document important decisions

When a task requires changing an established design or architectural decision:

1. Explain why the change is necessary.
2. Identify the affected documentation.
3. Update the appropriate ADR.
4. Update the relevant design or architecture document.

Do not silently alter the system.

## Rule 10 — Keep documentation synchronized

Whenever an implementation changes a reusable convention, design token, architecture rule, or project structure, update the corresponding documentation.

Documentation must describe the real current state, not an outdated plan.

## Rule 11 — Ask before making consequential assumptions

If an important requirement is unclear and different interpretations would lead to significantly different designs or architectures, ask one concise clarification question before proceeding.

For minor decisions, use professional judgment and document the assumption.

## Rule 12 — Explain implementation changes

At the end of every development task, provide:

- What was implemented.
- Files created or modified.
- Design decisions made.
- Responsive behavior implemented.
- Validation performed.
- Known limitations.
- Documentation updated.
